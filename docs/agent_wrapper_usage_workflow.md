# agent_wrapper 利用ワークフロー — 「仕様を固めてから外に出す」

作成: 2026-07-10
背景: 2026-07-10の実運用(Box3Dシーン実装のclaude依頼、ダッシュボードUX改善のcodex依頼)を
通じて確立した使い方の認識をテキスト化したもの。
関連: docs/agent_wrapper_permission_policy.md(許可設計)、agent_wrapper/README.md(操作手順)

## 1. このツールの位置づけ

agent-wrapperは「思いつきのタスクを雑に投げる道具」ではなく、
**仕様が詳細化された作業を、PCから離れても安全に実行させるための実行装置**である。

- 事前に /spec 等で「何を開発するか」を詳細化してから使うもの
- 曖昧なタスクをそのまま投げると、ラップされたエージェントの計画確認・会話質問・
  エスカレーションが増え、承認疲れ(許可設計ポリシー参照)の原因になる
- 依頼文(プロンプトファイル)の作成には **Claude Code / Codex を間に挟む** のが実運用の形。
  人間が依頼文を直接書くのではなく、対話で仕様を固めた上でAIに依頼文を書かせ、
  それをagent-wrapperに渡す

## 2. 推奨フロー(実運用で検証済み)

1. **仕様の詳細化**: /spec等でゴール・完了基準・制約を確定する(tasks/todo.mdに落とす)
2. **依頼文の作成**(Claude Code/Codexが行う): プロンプトファイルに以下を明記する
   - 対象(リポジトリ・ファイル・読むべきドキュメント)
   - 実装項目の具体的な列挙(todo.mdのセクション参照でもよい)
   - 制約: テスト必須・品質チェックコマンドとそのスコープ・**git commit禁止**
     (人間レビュー後にコミット)・dangerously系禁止・要求以上の機能追加禁止
   - 完了時の報告内容
3. **起動**: agent-wrapperを**デタッチした独立プロセス**として起動する
   (Start-Process等。監視役サブエージェントの子プロセスにしない —
   親の寿命に巻き込まれて強制終了される。tasks/lessons.md 2026-07-10参照)
4. **監視と承認の分離**: 監視は別のエージェント(観測のみ、/approve・/deny呼び出し禁止)、
   承認は人間がダッシュボード(QR/LAN URL/ntfy)から行う
5. **完了後のレビュー**: エージェントの完了報告を鵜呑みにせず、
   `git diff` 全体のレビューと品質チェックの再実行を人間側(またはClaude Code)が行う。
   UI変更はテスト通過だけでなく実ブラウザでの確認まで行う
6. **コミット**: レビューで問題なければ人間の承認を経てコミット

## 3. 実例(2026-07-10)

- **成功例1(claude)**: coin-diceの隣にBox3D版シーンを追加。既存調査ドキュメント
  (box3d-investigation.md)を参照させる具体的な依頼文で、約21分・人間承認12回・
  ollama自動承認47回で完走。既存実装を壊さず目的物が完成
- **成功例2(codex)**: ダッシュボードUX改善6項目。todo.mdの項目を依頼文に展開し、
  中断後も「作業ツリーの途中実装を引き継いで完成させよ」という継続依頼文で完走
- **失敗から学んだこと**: 監視サブエージェントの子としてラッパーを起動→60分で
  プロセスツリーごと回収され作業中断(起動と監視は分離する)。完了報告に
  「設計docstringの大量削除」「テストでは検知できないJS構文エラー」が含まれて
  いた(レビュー必須の根拠)
